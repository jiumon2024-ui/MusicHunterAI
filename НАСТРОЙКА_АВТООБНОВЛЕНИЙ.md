# Music Hunter AI — бесплатные обновления (0.9)

## Что уже работает в коде

- Кнопка «↻ Обновления»: настройка ссылки на **публичный репозиторий GitHub**, автоскачивания, ручной проверки.
- При открытии приложения проверяет GitHub Releases, не чаще одного раза в 6 часов (или вручную).
- Если версия новее, предлагает скачивание; если включена автозагрузка — ставит APK в системные «Загрузки».
- Загрузка выполняется через системный DownloadManager, который показывает своё уведомление.
- **Установка требует подтверждения Android**. Никакой бесшумной установки или обхода защиты нет.
- Интерфейс на русском; на телефонах нет платных API, аккаунтов GitHub, токенов или кредитов.

## Как настроить публикацию для всех телефонов (один раз)

1. Создайте **публичный репозиторий GitHub** для проекта и отправьте туда исходники. Это опубликование исходного кода: не загружайте секреты, личные файлы и пароли.
2. Создайте **один постоянный закрытый ключ подписи Android** (keystore). Сохраните ключ и пароли в резервной копии, вне репозитория. Если потеряете ключ, выпущенный APK больше нельзя будет обновлять без переустановки.
3. В разделе GitHub репозитория Settings → Secrets and variables → Actions создайте четыре секрета:
    - `MHA_KEYSTORE_BASE64` — содержимое keystore-файла, закодированное в Base64;
    - `MHA_KEYSTORE_PASSWORD` — пароль хранилища;
    - `MHA_KEY_ALIAS` — имя ключа;
    - `MHA_KEY_PASSWORD` — пароль ключа.

   Base64 в PowerShell Windows (локально, никому не отправляйте вывод):
   ```powershell
   [Convert]::ToBase64String([IO.File]::ReadAllBytes('C:\путь\к\music-hunter-release.jks'))
   ```

4. Отредактируйте `app/build.gradle.kts`: при каждом выпуске `versionName` и `versionCode` должны увеличиваться. Используйте правило `versionCode = major * 10000 + minor * 100 + patch`, например `0.6.0` → `600`, `0.6.1` → `601`.
5. В корне проекта дважды нажмите `PUBLISH_UPDATE.cmd`. Скрипт показывает изменения, запрашивает подтверждение и отправляет тег вида `v0.6.0` в GitHub. Вы должны заранее настроить Git for Windows, доступ к своему репозиторию и `origin`.
6. GitHub Actions (`.github/workflows/publish-apk.yml`) соберёт подписанный `MusicHunterAI.apk` и разместит его в GitHub Releases. Внешние тарифы GitHub Actions могут иметь свои ограничения, но отдельный платный ИИ или сервер здесь не нужен.
7. В APK, собранном GitHub Actions, адрес GitHub-репозитория уже прописан автоматически: на телефонах источник обновлений вводить не требуется.

В обычной тестовой сборке из Android Studio GitHub-адрес не встроен. В ней можно нажать «Обновления» и указать `имя-владельца/имя-репозитория` вручную.

## ВАЖНО: первый APK и подпись

`app-debug.apk` из Android Studio — **отладочный APK**, он подписан отладочным ключом. Он, как правило, не обновляется поверх подписанного release-APK, собранного GitHub Actions. Для перехода от тестовой версии к рабочей удалите debug-версию, предварительно сохранив свои данные, и установите первый подписанный release APK. **Следующие release-версии должны подписываться тем же ключом.**

Просто нажать Build на компьютере недостаточно для публикации: GitHub должен получить исходники и тег выпуска. В нашей схеме это делает один скрипт после вашего подтверждения.

## Что не реализовано

- Гарантированная установка и проверка в строго заданную минуту: системный планировщик Android может откладывать фоновую проверку примерно на 12 часов.
- Тихая установка без подтверждения Android.
- Публикация в Google Play: там действуют отдельные требования, в том числе к механизму обновления.
